The idea

Put the key on the phone. Ask the person.

  • Possession: an EC P-256 key generated in the phone’s secure hardware.
  • Approval: every sign-in is one visible request, confirmed with the phone’s own biometric lock.
  • Origin-bound: the signed message names the site, so a relayed QR is self-evidently for the wrong one.
  • No shared secret: the server stores a public key, never anything that can be replayed.

The flow

Five steps, about four seconds

1

Request

The site mints a one-time request: id, nonce, origin, 120-second life.

2

Scan

The QR — or a tap on the same phone — hands the request to the app.

3

Approve

The app shows the site and account; the phone’s lock authorises the signature.

4

Verify

The server checks the signature against the enrolled public key and the origin.

5

Session

The browser that started the request gets the session; the request is consumed.

Security model

What the server can and cannot see

On the phone

  • Private key generated in Android Keystore / TPM; never exported.
  • Signature requires the device lock — enforced by the key itself.
  • Attestation chain proves TEE, StrongBox or TPM, where present.

On the server

  • Public key, label, last-used time, attestation verdict.
  • No shared secret, no password to brute-force, no replayable token.
  • Origin is checked; a QR relayed from another site cannot verify.
Attested

TEE · StrongBox · TPM · software, shown honestly per device.

Bound

Signature covers site, request, nonce and time.

Throttled

Rate limits on every unauthenticated endpoint.

Revocable

One device, one account, instantly, from the profile page.

Operations

Boring to deploy, easy to undo

One command

The Windows installer detects a paired PC, installs the tile, hides the password provider, gates SSH, sets RDP and logon rights — and can keep every change instead of timing out.

guided-install.ps1 -Unattended -ServerUrl … -PairingCode …

Reversible by default

Every hardening step saves its previous state and can arm a timed rollback; the installer passes -Keep only when you mean it.

-Keep · -SignInGroup "Thessley Sign-in"

Tested, not assumed

Behavioural suites, HTTP end-to-end, real EC signatures, and Plugin Check in CI-shaped runs. Compatibility: WordPress 6.0+, PHP 8.3.

Self-hosted

No external service, no telemetry, no phone-home. QR codes are generated locally; keys and audit data stay on your infrastructure.
