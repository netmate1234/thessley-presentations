How it works

Four steps, no server of ours in the middle

1

Show

The computer shows a QR with its LAN address, port, certificate hash, request id and user.

2

Pin

The app trusts only the certificate named in that code, so the screen authenticates the computer.

3

Sign

After the phone’s unlock, the app POSTs an approve/deny signed with ECDSA P-256.

4

Check

The computer verifies against the user’s enrolled public keys and accepts exactly one answer.

Trust model

The computer only ever holds a public key

On the phone

  • Key generated in Android Keystore, hardware-backed where available.
  • Every signature requires the device’s own unlock.
  • Nothing leaves the device but the signature.

On the computer

  • Enrolled public keys only, under root-owned state.
  • One-time request id and nonce; one answer per request.
  • Certificate pinning, so a look-alike host cannot collect approvals.

SSH

The key and the phone, then four quiet hours

  • Group policy decides who is gated: key + QR, key + password recovery, or no SSH.
  • One approval covers the same user, service and client address for 4 hours; then it asks again.
  • Per-user overrides, stored root-only, applied with sshd -t + reload.
  • The rollback timer can restore the previous sshd_config and PAM files.
