Protocol

What every request carries

Request

Type (login/enroll), id, nonce, origin, 120-second life.

Signature

ECDSA P-256 over a pipe-joined string: version, type, id, origin, nonce, time, action.

Verify

Public key of the enrolled device; timestamp within 60 s; origin must be this site.

Consume

Exactly one answer per request; the browser that started it collects the session.

Two servers

Same protocol, different page around it

WordPress

  • Reference implementation inside the plugin.
  • “App only” asks for the username first, then falls back to the password form for an account with no device.
  • Three modes: optional, 2FA, app-only.

Drupal 10.3 / 11

  • Standalone module, cleaner and self-contained.
  • Hides the password form in app-only; ?thessley_password=1 is the way back.
  • Same endpoints, same signatures.

Optional proof

Verify that a key lives in a TPM

  • The client sends its endorsement-key certificate chain and attestation key.
  • The server checks the chain against the shipped vendor roots (tpm-roots/).
  • It builds a credential challenge, then verifies the certification and secret activation.
  • The device is recorded as TPM-verified; sites show that honestly, or “software”.
